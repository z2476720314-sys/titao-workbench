# 多模板说明

一个图案要同时上多种壳型时，不用重复操作 —— 一次选中多个模板即可。这里说明多模板的
组织方式、输出结构，以及容易踩的几个点。

## 一次跑多个模板

「套图」页的**套图模板**支持多选文件，也支持直接选目录（只展开一层）。

引擎内部把「图案 × 模板」展成任务列表（`internal/jobs/engine.go` 的 `expand`），
每个组合是一个独立任务，顺序执行：

```
图案 A × 模板 1  →  任务 #1
图案 A × 模板 2  →  任务 #2
图案 B × 模板 1  →  任务 #3
图案 B × 模板 2  →  任务 #4
```

任务队列页里每条任务都有自己的进度、耗时和结果，失败的任务不影响后续任务。

## 输出结构

```
<输出目录>/<图案名>/<图案名>_<模板名>_NN.jpg
```

举例：图案 `подсолнух 2`，模板 `紫色IMD模版1`、`粉色IMD模版2`，每个模板切 6 格：

```
<输出目录>\подсолнух 2\
    подсолнух 2_紫色IMD模版1_01.jpg
    подсолнух 2_紫色IMD模版1_02.jpg
    ...
    подсолнух 2_紫色IMD模版1_06.jpg
    подсолнух 2_粉色IMD模版2_01.jpg
    ...
    подсолнух 2_粉色IMD模版2_06.jpg
```

同一图案套多个模板时，**成品都在同一个图案名目录下**，靠文件名区分模板。
这样按图案整理素材时不用来回翻目录。

单图案时可以手动改目录名（「图案」区勾选单文件后出现的「名称」输入框，对应
`Options.PatternName`），多图案时这个框被忽略。

## 每个模板独立判档

摆放倍数（`auto` 模式下的视觉模型判档）是**按任务独立**的。同一图案套两个尺寸不同的
模板，会各自渲染候选、各自问一次模型，选出的倍数可以不同。

这是有意的：不同壳型的壳面比例不一样，1:1 置入对 A 模板刚好，对 B 模板可能就偏了。
代价是每个组合都要多花几次模型调用 —— 想省额度就把「视觉模型自动判断图案大小」关掉，
所有模板统一用候选组的第一档。

## 格边长（cell_size）是全局参数

切格按 `cell_size` 纵向切，默认 800。**它是全局的，不是每个模板各一份**。

如果某个模板的分割线间距不是 800，有两种处理：

1. 在「套图」页的**格边长**里填该模板的实际间距，一次只套这一个模板；
2. 用「探查结构」先看模板的真实间距（`ProbeTemplate` 从 TIFF Guides 推
   `Guides[1] - Guides[0]`，探不到才退回 800），确认后再批量套。

多模板混着不同间距时，按间距分组、分几批套。

## 模板只读

模板永远是**复制进临时目录再打开**（`engine.go` 的 `tplCopy`），原文件不动。
所以同一批模板可以反复套，不用担心被改坏。图案同理。

## 已知限制

- 目录选择只展开一层，不递归。子目录里的模板不会自动带上。
- 每个任务独立开临时目录，跑完即清；中途失败时临时目录会被保留便于排查。
- 模板的智能对象必须放在指定的顶层图层组里（默认「插画」，对应配置 `group`）。
  组名对不上就一个格子都不会被替换，日志里会看到 `MISS ` 行。
