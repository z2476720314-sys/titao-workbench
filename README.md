# 套图工作台

通过 Photoshop 或 PhotoCraft，把透明图案套进分层 TIF 模板的智能对象，按模板分割线（默认每 800px 一格）切出手机壳 JPG；
再把套好的上架图交给生图大模型，生成新的手持图或换背景图。

- 模板与图案都只读，程序永远复制到临时目录再动，源文件与文件名绝不改动
- 默认按原比例完整放下并居中，模型只在主要内容存在问题时微调
- 套图前先做视觉预检，自动跳过带水印、带镜头框、是手机壳实拍的图
- 支持暂停 / 继续 / 停止，队列落盘，关掉程序再开能接着跑
- 单文件 exe，不依赖 Python 或环境变量

## 用法

双击 `build/bin/套图工作台.exe`。侧栏六个页签：

| 页签 | 作用 |
|---|---|
| 套图 | 选图案与模板、调摆放参数、开始 / 暂停 / 停止 |
| 任务队列 | 每个「图案 × 模板」组合的实时进度、轮数、耗时 |
| 生图 | 拿套好的图当参考图，生成新手持图或换背景图 |
| 成品 | 浏览输出目录里的成品，可打开所在文件夹 |
| 设置 | 视觉模型、生图模型、默认路径、默认套图参数、微调与预检、更新 |
| 关于 | 版本、配置文件位置、输出目录、Photoshop 能力诊断 |

启动工作台不会启动 Photoshop 或 PhotoCraft，状态显示“待启动”；首次通过预检并需要渲染时才连接所选套图引擎。

### 套图页

- **图案**：透明 PNG / JPG / TIF / WEBP，可多选文件或直接选目录（只取一层）
- **套图模板**：PS 分层 TIF，可多选或选目录。**一个图案可以同时套多个模板**，页面实时显示 `N 图案 × M 模板 = K 组`
- **探查结构**：引擎首次启动后，可查看模板里的智能对象、分割线间距和格数
- **图层组**：默认「插画」，只替换该顶层组里的智能对象，底图与背景不动
- **摆放方式**：
  - `auto`（推荐）完整放下 —— 以「图案整体可见」为基准，配合下面的「不裁切」自动收敛
  - `contain` 完整放下（同 auto，显式指定）/ `cover` 铺满裁切 / `stretch` 拉伸 / `none` 原始像素
- **图案必须完整可见（不裁切）**：默认开，透明图案完整保留。自动模式中，无透明底的完整背景设计直接等比满铺，允许略裁边缘背景，主要人物、文字和标志仍需完整。
- **视觉模型自动判断图案大小**：默认 auto / contain 按 1.0 基准渲染：无透明底直接满铺，透明图案在原画布底部有内容时贴底，底部透明的独立文字和标志居中。主要内容完整、无明显遮挡就直接通过；确有主体问题才微调，满版图调整后仍须铺满，最多评审 `max_rounds` 轮。
- **手动档位**：逗号分隔，留空用配置里的候选
- **水平/垂直微调**：占画布宽/高的比例，`0.1` = 右移 10%
- **格边长**：默认 800，与模板分割线一致
- **裁掉图案四周透明留白**：默认开，让图案真正居中且尺寸准确
- 自动模式下，预检确认的连续满版背景会按当前 2:1 印刷画布只续铺顶部缺口，不裁切原图；人物、文字及标志仍完整保留，不续铺。
- **暂停 / 继续 / 停止**：暂停粒度是「一整组」（当前这组跑完才停，Photoshop 不能中途掐断）；停止立即中止，已出的图保留

### 生图页

拿套好的上架图当参考图，让生图模型产出新的商品图。

- **参考图**：选一张或多张已套好的图（可从成品页直接带过来）
- **生成方式**：新手持图 / 换背景图，可同时勾选
- **每种模式生成张数**：用户手动设置，1~10。生图接口每次只出 1 张，要 N 张就循环调用 N 次
- **提示词由视觉模型看参考图后生成**，强约束手机壳本身（图案、颜色、比例、摄像头开孔、材质）必须与参考图一致
- **一致性校验**：每张生成图再过一遍视觉模型比对参考图，不一致自动重试一次，仍不一致标失败并保留产物
- 尺寸默认 `1024x1024`（1:1、1K）

### 输出结构

```
<输出目录>/<图案名>/<图案名>_<模板名>_NN.jpg
```

首次运行的模板、图案和输出目录均为空，请在界面选择并保存。已有配置中的路径保持不变。同一图案套多个模板时，成品都在同一个图案名目录下，靠文件名区分模板。

预检记录写在 `config.json` 同目录的 `precheck.jsonl`，一行一个文件，
用 `path + size + mtime` 三元组命中才算已处理 —— 文件任一属性变化就重新判，避免重复烧模型额度。

预检会检查整图与放大局部，整体通过后再分别查独立圆角壳面和细小水印；每张素材最多 6 项检查，同一素材跨模板复用记录。临时连接故障或 5xx 最多各重试一次。无法确认的残字不会作为合格缓存。规则版本升级会重新检查旧记录。
Claude 视觉模型自动省略不支持的自定义 `temperature` 与代理思考开关；DeepSeek 保留原有参数。
GPT-6 Luna 使用原生 `max_completion_tokens` 和 `reasoning_effort`；思考开关关闭时为 `none`，开启时为 `medium`。

## 配置文件

  "offset_x": 0,
  "offset_y": 0,

  // 生图模型
  "gen_base_url": "https://junli1.junlistudio.com/v1",
  "gen_api_key": "",
  "gen_model": "gpt-image-2.5",
  "gen_size": "1024x1024",
  "gen_thinking": false,

### candidates 怎么定

`t` 是相对「完整放下」的倍数：`1.0` = 图案完整可见且至少一个方向顶到壳边（不裁切上限），`<1` 留白，`>1` 会超出壳面被裁。

区间必须覆盖「明显偏小 → 明显超出」。实测：把候选换成 `[0.3,0.45,0.6,0.75]` 模型会选 `0.6`，换成 `[0.75,1.0,1.25,1.5]` 会选 `1.25` —— 它只在组内做相对比较，区间一窄选出的 t 就漂移。

## 核心机制

1. **图案规范化**（`internal/imgutil`）：始终经 Go 重存 PNG。原始 PNG 若带 300dpi 元数据，PS 会按物理尺寸换算导致图案缩小 4 倍 —— 重存一次就没这问题。可选裁掉 alpha bbox 外的透明留白。
2. **视觉预检**（`internal/precheck`）：模型逐项识别水印、镜头框、壳体轮廓和壳实拍，代码汇总是否拦截。问题图跳过；严格预检下，读取/模型/解析失败标记当前任务失败，其他任务继续。缓存包含规则版本，新版会重新检查旧记录。
3. **模板复制**：模板先复制进临时目录再打开，原文件只读不写。
4. **智能对象替换**（`internal/psx`）：进 SO 内部编辑，把图案按档位缩放置入内部文档（945×1890 画布），保留外层变换。同一 PSB 被多个格子共享时只替换一次，所有格子一起更新。
5. **候选渲染**：一次 PS 会话里按各档各导一张整幅拼合图。
6. **视觉模型选档**（`internal/judge`）：原图参考加第一格候选，明确 fit、不裁切、候选实际倍率和偏移。DeepSeek 使用原生 thinking 开关与 JSON 输出模式，保留原代理字段兼容。
7. **多轮评审微调**（`internal/tuner`）：每轮渲染后均评审，包括最后一轮；无有效参数变化即停止。模型失败或后续效果变差时保留评分最高的已评审候选。未通过仍导出，但明确提示人工复核，提示随队列持久化。
8. **切格导出**：按 `cell_size` 纵向切分，逐格写 JPG。

## PS 版本兼容

### PhotoCraft

设置页可选择 `PhotoCraft`，保存后重新打开工作台生效。`photocraft_cli` 留空会检测系统 Program Files 中的安装位置，也可填写实际 `photocraft-cli.exe` 路径；配置中的 `renderer` 为 `photocraft` 或 `photoshop`。旧配置默认 Photoshop。

PhotoCraft 使用本机无界面 MCP，每次渲染仅授权任务临时目录，不打开桌面窗口、不建立网络监听。读取嵌入智能对象的实际画布尺寸，生成透明内容后替换，保留外部变换、蒙版和共享实例。当前版本已对现有五份模板执行真实渲染与原文件校验。

`auto/contain` 默认等比贴底，左右居中；不裁切时倍率与位移都限制在内容画布内。相机和手指等原模板遮挡仍保留，不代表完整图案的所有位置都能在成品上看到。

DeepSeek 参数依据：[Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)、[JSON Output](https://api-docs.deepseek.com/guides/json_mode/)。代理是否遵从仍以真实返回为准；当前模型的评分属于辅助判断。

### Photoshop

`internal/psx/capability.go` 的 `For(version)` 按 PS 大版本判定能力：

| PS 大版本 | Verified | 说明 |
|---|---|---|
| 27（2025） | ✅ | 实测通过，本项目主目标 |
| 13–26 | — | 保守放行，标注「未实测」 |
| < 13（CS6 之前） | — | 缺 `placedLayerEditContents`，套图功能不可用，报错提示升级 |
| 未知 / 空 | — | 保守放行，标注「版本未知」 |

`ReplaceContents` 在任何版本都是 `false`。实测 `placedLayerReplaceContents` 会把智能对象原有透视变换从 271×601 放大成 1331×3211，成品完全错位，所以本项目永远走 `placedLayerEditContents` 进内部文档替换这条路。

### 浏览器端口审查（打包前必做）

桌面窗口会抢焦点、妨碍干别的活，所以界面验收走浏览器：

```bash
cd frontend && pnpm install && pnpm run dev     # http://localhost:5180
```

- 打开 `http://localhost:5180/review.html?view=run` —— `review.html` 只加载 `src/mock.ts`（完整假后端），
  不驱动 PS、不烧模型额度，可点遍每个按钮看反馈
- `?view=` 支持 `run / tasks / gen / outputs / settings / about` 六个页签直达
- `window.__mock` 提供状态切换：`pause() resume() idle() pending() noPending() emptyTasks() fillTasks() genIdle() genRun() genKey(on) log(level,msg) event(ev)`
- 生产 `index.html` 仍走 `src/main.ts`，构建产物里不含 mock（`grep -c "__mock" dist/assets/*.js` = 0）

界面验收全通过后再 `wails build` 打 exe。

### 端到端探针

`cmd/probe` 不经 GUI 直接驱动引擎跑一次真实套图，所有路径必须显式传入。路径含空格、中文或其他文字时加引号：

```text
go run ./cmd/probe -config "<配置目录>" -pattern "<图案文件>" -template "<模板文件>" -out "<输出目录>"
```

`cmd/precheck-sample` 用真实图库抽样验收预检，不修改图库；结果追加到配置目录中的 `precheck.sample.jsonl`，保留历史记录，不影响正式预检记录：

```text
go run ./cmd/precheck-sample -config "<配置目录>" -dir "<图库目录>" -n 24
```

`-config` 必须包含已有 `config.json`。`-n` 必须大于零，`-start` 为非负索引，`-stride 0` 表示自动步长。两个工具均拒绝错误参数。`probe` 对任务失败、零导出或无效导出文件返回非零状态；它沿用套图引擎的模型失败回退策略。`precheck-sample` 对模型、图片或记录写入失败返回非零状态，模型失败不计作合格样本。

## 自动更新

设置里 `update_check` 默认开。启动后只检查并提示新版；用户点击“下载并更新”后下载 EXE 和对应 SHA256，校验通过才安排替换。运行任务期间不能安装更新。脚本等待旧进程退出后覆盖原 EXE 并启动新版，不覆盖 `config.json`、队列或预检记录。下载暂存在程序所在目录，不使用全局共用更新包目录。

全程静默失败：网络不通、被限流、仓库 404、预发布/草稿都只返回 error 不打断用户。替换脚本最多重试 60 次，仍失败就提示手动替换，不会把程序搞成打不开。

## 已知限制

- 视觉模型接口偶发超时，此时回退到候选组里中间偏小的一档（宁可略小也不裁坏），日志会标「视觉模型判断失败」
- 目录选择只展开一层，不递归
- 需要 Photoshop 已安装并可被 COM 调用；PS 若弹出模态对话框，COM 调用会挂起
- 生图接口每次只出 1 张，要 N 张就循环 N 次，耗时线性增长
